# P16 CS42L43 speaker route DKMS package

This package replaces the in-tree `mt8901_acp_sdw_legacy_mach` platform driver with a copy of the current upstream driver plus four static DAPM routes from the card's `Speaker` endpoint to the CS42L43 AMP1/AMP2 positive and negative output pins. The routes are enabled only when all three exact DMI fields identify `ASUS`, `ProArt P16 H7607BA`, and board `H7607BA`, and ACPI device `NVDA6210` is present. Other boards continue to use the upstream route table unchanged.

The source is copied from `work/n1x-upstream-pr/integrated-source/sound/soc/mediatek/mt8901/mt8901-acp-sdw-legacy-mach.c`, whose SHA-256 is `1136655fcf885059e1f6c9e2184d9e6335c84f9fd9203e9adb10431fd3d0d2fc`. Only DMI/ACPI includes, the exact board guard and the four routes/table composition were added. See `provenance/upstream-source.txt`.

DKMS automatic builds are restricted to exact kernel releases: `7.3.0-7-omarchy-n1x-coordinated1`, `7.3.0-8-omarchy-n1x-pr1958-1`, `7.3.0-9-omarchy`, and `7.3.0-9-staticduo-p16`. The P16 builder evidence confirms that the latter release's `mt8901-acp-sdw-legacy-mach.c` is byte-identical to the reviewed base snapshot (SHA-256 `1136655fcf885059e1f6c9e2184d9e6335c84f9fd9203e9adb10431fd3d0d2fc`). Its packaged kernel headers have not yet passed a DKMS build gate. Treat successful compilation against those exact headers as a prerequisite to installing this package on that release; the source identity alone does not verify generated header compatibility, module signing, or runtime behavior. DKMS skips other releases. This module replaces the complete in-tree machine driver, so review the upstream source delta and compile/test against a new kernel before adding it to `BUILD_EXCLUSIVE_KERNEL`; do not broaden the allowlist just because the ABI still compiles.

The Arch package installs only DKMS source under `/usr/src/p16-audio-route-0.1.0`; the `dkms` package hooks add/build/install it for supported kernels. Header packages remain kernel-specific optional dependencies supplied by the selected kernel package. Do not hot-reload this replacement driver: a live rmmod/modprobe reprobe was observed to leave CS35L56 in a failed calibration state, and reloading the codec module can also lose required controls when the version-qualified firmware is not shipped. Validate final audio after a cold boot using a kernel that contains the host's accepted SoundWire patch set; the relevant SoundWire slave fixes are gated on a system BIOS reboot.

Build with `makepkg -sf`; this only creates a package. Install/reload and physical audio validation are separate steps. `tests/test_route_patch.py` checks the patch scope and hardware gate.
